New versioned research namespace. Preserve all v0.1 tasks, runs, policies and artifacts unchanged. Public deployment becomes read-only (no paid requests by visitors). Research commands use the EXISTING spend ledger and credential; never reset its accounting. No arbitrary repository uploads, shell commands, filesystem or network tools.

## Task contract
Frozen RepoTask: id, title, family, split (train/validation/test), category (bug_fix/multi_file/feature/refactor/failing_tests/long_horizon), difficulty, summary, description, files: dict[str,str], reference_files: dict[str,str], entrypoint: str = 'service:run', public_cases: tuple[dict,...], hidden_cases: tuple[dict,...], allowed_edit_files: tuple[str,...], success_criterion: str, tags: tuple[str,...].
Flat Python module filenames only (e.g. service.py, rules.py, helpers.py); no paths, packages or __init__. Local imports supported. Entrypoint module:function, pure JSON-in/out callable. Cases compatible v0.1 ({name,args,kwargs,expected[,expected_error]}). Up to 24 cases/group; files total <=40KB, <=8 files. At least2 meaningful linked modules for multi-file tasks. Each task has visible failing reproduction, nontrivial hidden edge/regression cases and a correct reference implementation. Fixed 50 tasks/10 distinct families, split30/10/10, disjoint families. Original authored miniature repositories; long_horizon is a multi-requirement stress category, NOT empirical evidence of real-world long-horizon capability. Reference and hidden test definitions must NEVER be exported by public_task or sent to provider.
Functions: list_tasks(), get_task(id), public_task(task,include_cases=False), task_manifest_hash(). public_task includes files/entrypoint/allowed_edit_files/success_criterion, public test inputs+expectations only if include_cases. Validation tests cover uniqueness/disjoint splits/expected changes and goldens via real Docker (opt-in).

## Execution and provider
bench.sandbox.evaluate(task, files:dict, hidden=False) -> v0.1-compatible result + execution diagnostics. Networkless read-only rootless Docker; no host execution of candidate source. Flat modules loaded in memory INSIDE runner only. Test expectations remain in trusted host. Validate paths, bounded files, AST/import graph, protected-file edits. Existing v1 payload supported.
bench.provider.RepoProvider.generate(task, files, feedback, action, seed=0, run_id=None) async -> object with files (candidate full mapping or edits merged by engine), model, prompt_tokens, completion_tokens, cost_usd, elapsed_s, request_id, finish_reason, prompt_messages (actual sanitized outbound messages), response_text (visible content only). action 'cheap'/'strong'. Errors reuse ProviderError/BudgetExceeded and retain reservations. Model defaults remain existing Runpod endpoints until alternative configured and verified. GPT-OSS20B not falsely claimed measured.

## Engine and study
Policies strong_only, cheap_only, escalate_on_failure, static_router, adaptive. Router actions retry/repair/escalate/rollback/stop with legal bounded transitions. Same max6 model calls, max10 decisions per run for all policies. Stop on full visible pass; hidden tests only once AFTER policy decisions. Rollback to last best visible checkpoint, not hidden score. Learned artifact fitted exclusively on train transitions; unseen state fallback declared per action. Freeze config/hash before validation/test; never select by test results. Record prompt, files supplied (context, not a claim of autonomous reads), actual tool calls, candidates/unified patches, tests/errors/retries/model switches/rollback/final. No hidden chain of thought. Model-only closed-loop repair agent, not arbitrary tool-using agent; distinguish orchestrated tool executions.
Metrics: solved, public_passed/total, heldout_passed/total, cost_usd (estimate), tokens, elapsed_s, tool_calls, steps/attempts, regressions_introduced (previously passing visible cases made failing), unnecessary_edits (explicit proxy edits outside declared required files if available, otherwise null), success_after_repair, escalations, failure_labels (observed proxies, not causal attributions).
Study output at artifacts/forgebench/v0.2/: benchmark.json {version,status,generated_at,task_count,models:[],policies:[],summary:[],coverage:{planned,completed,missing},runs:[RunSummary],limitations:[],provenance:{}}, runs/<id>.json with full episode. Benchmark summary fields policy,n,solved,solve_rate,hidden_test_pass_rate,mean_cost_usd,mean_tokens,mean_latency_s,mean_tool_calls,mean_steps,mean_regressions,success_after_repair_rate,escalation_frequency,unnecessary_edits:null unless measured. Default CLI plan only. Training outputs transitions.jsonl and frozen controller.json. Append/fsync evidence after every episode. No fabricated runs. Preserve incomplete coverage and infrastructure errors. Bootstrap by task (paired policies), not treating seeds as independent tasks. Budget stop preflight + retained reservations shared durable ledger.
